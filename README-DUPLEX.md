# pico-dac2: combined USB playback + digital I2S capture

This is an additive full-duplex firmware build for the existing `pico-dac2`
repository. It keeps the original DAC playback path and adds a second UAC2
AudioStreaming interface for capture. The same Pico USB device should appear
in both `aplay -l` and `arecord -l`.

## What this build exposes

- Existing UAC2 playback interface, including the original 16/24/32-bit
  playback alternates and playback feedback endpoint.
- New UAC2 stereo capture interface: 44.1/48/88.2/96 kHz, S32_LE, 32-bit I2S slots.
- I2S TX remains on GPIO22, with BCLK GPIO20 and LRCLK GPIO21.
- New I2S RX is on GPIO23 and samples the same BCLK/LRCLK generated by the
  existing DAC TX PIO.
- PIO + DMA are used in both directions. TX retains DMA IRQ 0; RX uses
  DMA IRQ 1 so the two DMA completion handlers do not collide.
- No analog ADC is used. Capture is entirely digital I2S PCM.

## Build

Build one combined firmware; there is no separate ADC-only target:

```bash
cmake -S . -B build-duplex
cmake --build build-duplex -j"$(nproc)"
```

The UF2 is:

```text
build-duplex/mdac_adc2.uf2
```

Flash this same combined firmware onto the Pico being tested.

## USB verification

After the Pico reboots, its USB audio function should appear in both lists:

```bash
aplay -l
arecord -l
cat /proc/asound/cardN/stream0
```

The same card should advertise playback and capture. Capture uses stereo S32_LE and follows the shared UAC2 clock rate (44.1, 48,
88.2 or 96 kHz). The existing DAC playback formats/rates are retained.

## First digital loopback test

This first combined build has a local I2S clock master and a digital I2S input.
Before adding the remote Pico's clock-slave transmitter, verify the complete
USB playback-to-I2S-to-capture path with a short jumper:

| Pico GPIO | Connection |
|---|---|
| GPIO22 | I2S TX DATA output |
| GPIO23 | I2S RX DATA input; connect GPIO22 to this pin |
| GPIO20 | BCLK generated by the TX PIO and observed by RX PIO |
| GPIO21 | LRCLK generated by the TX PIO and observed by RX PIO |

The GPIO22-to-GPIO23 jumper loops the digital transmit data back into the
receiver. No analog audio wiring is involved.

Find the combined Pico's card number in `aplay -l` and `arecord -l`. Start a
48 kHz stereo S32_LE test tone on its playback device, then record from its
capture device (replace `N` with the same Pico card number):

```bash
speaker-test -D hw:N,0 -c 2 -r 48000 -F S32_LE -t sine -f 1000
```

In a second terminal:

```bash
arecord -D hw:N,0 -f S32_LE -c 2 -r 48000 -d 10 /tmp/pico-loopback.wav
```

The captured WAV should contain the looped-back test tone. The capture path
will be silent until the I2S TX is streaming and generating clocks.

## Scope and known limits

- This is one USB device with playback and capture endpoints active together;
  it is not the completed two-computer bridge yet.
- Capture uses 32-bit I2S slots and supports the existing shared clock rates.
  Use S32_LE playback while testing capture; the 16/24-bit playback alternates
  have narrower I2S slots and are not compatible with this receiver.
- The second Pico's clock-slave I2S transmitter, which will drive DATA back to
  this Pico over the shared clocks, is a subsequent implementation step. Do
  not connect two clock-master outputs together.
- The asynchronous capture packetizer uses a small FIFO-fill correction loop;
  sustained-clock stability still needs hardware validation.
